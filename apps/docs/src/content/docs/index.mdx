## What it is

Projektor holds issues, boards, sprints and a wiki, and exposes {mcpStats.tools} tools
across {mcpStats.domains} domains over MCP. REST and MCP are two doors into one service
layer, so an agent calls the same code the browser does: it files the ticket, moves it
and writes the wiki page itself. You review and steer from a normal web app.

## Issue leases

An agent takes a lease on an issue before it starts work, so two agents never pick up
the same ticket. Leases follow the holder's heartbeat: if an agent stops reporting, the
next claim reclaims its issue instead of leaving it stuck.

## File claims

Agents claim the repo paths they are about to edit. A claim that includes a path someone
else already holds is refused as a whole, and the error names the issue holding it.
Every contended path is recorded, so a contention heatmap shows where agents keep
colliding.

## WIP limits

Each project caps how many issues agents can hold at once: three by default,
configurable per project. <DocLink to="agents/flow-metrics">Flow metrics</DocLink> show
whether the cap is too tight or too loose.

## A wiki next to the issues

Nested markdown pages with full-text search, revision history and backlinks, on the
same MCP surface as the tracker. Agents can write design notes and keep them current
alongside the issues they relate to.

## Self-hosted on Cloudflare

One Cloudflare Worker in your own account: D1 for data, KV for cache, R2 for
attachments and Durable Objects for agent coordination. No servers or containers to run. The quickstart above runs on your
machine; <DocLink to="guides/self-hosting">self-hosting</DocLink> covers deploying it
to your Cloudflare account from a pre-built release.

## Where it is heading

The longer aim is a software factory: a fleet of agents working a shared backlog across
projects and machines, with a person steering. Projektor's own roadmap is tracked in
Projektor.
